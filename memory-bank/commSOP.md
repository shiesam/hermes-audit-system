# commSOP.md — 跨平台通訊與遠端操作鏈

> 對應 V6.0 §1-3 跨平台通訊與遠端操作鏈。這裡放通訊規則與原則本身，
> 實際帳號/金鑰/連線參數不寫在這裡（機密資訊不進版本控制），只描述規則與流程。

## 1-3-1 通訊鏈維護與 API 自癒

- 斷線 / Timeout 時，Agent 必須自動嘗試重新連線，不可直接判定任務失敗就停止。
- 金鑰/憑證若過期或失效，需有自動偵測與修復流程（例如重新讀取設定檔、提示人補發新金鑰）。
- 若自動重連/修復多次仍失敗，才升級為 incident 通知人介入（見 `systemPatterns.md` 的 watchdog 機制）。

## 1-3-2 LINE 訊息與推播控制

> ⚠️ 待補：目前尚未整合 LINE 推播，以下為規則骨架。

- 異常事件（如 incident 產生、任務卡住超過門檻）→ 應主動推播通知，不要等人來問。
- 工程重要節點（例如審圖完成、關鍵決策待確認）→ 發送確認提示，等待人回覆才繼續。
- 待補：LINE Notify / LINE Bot 的串接方式、Token 存放規則（存在環境變數，不寫入程式碼或本文件）。

## 1-3-3 多端同步與硬體存取

> ⚠️ 待補：目前系統只有主機（Linux）與蝦米（Windows）兩端，尚未涵蓋手機、iPad。

- 目標：手機、筆電、iPad 之間的資料要能跨裝置同步。
- 目標：支援遠端指令發射與目錄瀏覽（例如從手機下指令，主機執行）。
- 現況：目前僅主機↔蝦米透過共享 SQLite（`agent-mesh.db`）協作，詳見 `techContext.md` 環境速覽。

## 1-3-4 禁開 UI 介面原則

**鐵律：凡批次轉檔 / 資料處理，嚴禁操控 GUI 或寫死 LISP，優先使用 CLI 命令行與 Python subprocess。**

- 例如：DWG/DXF 批次轉檔，應呼叫 ODA File Converter 的命令行參數，而不是用滑鼠點擊操作介面。
- 原因：GUI 操作無法被 Agent 穩定重現、無法寫入自動化流程、容易因視窗位置/解析度不同而失敗。
- 若某項工具沒有 CLI 介面可用，須先向人回報，討論替代方案，不可擅自改用 GUI 硬做。

## 1-3-5 自我修復閉環（Self-Healing Loop）

流程：

1. 指令或腳本執行跳錯 → 自動擷取 Error 訊息。
2. 將錯誤訊息餵回 AI（同一顆或另一顆模型）進行判斷。
3. 若判斷是可修復的問題（例如 API 額度用盡、連線暫時失敗）→ 自動切換到其他可用的免費 API 繼續工作。
4. 若判斷無法自行修復 → 停止並標記為 `input-required`，寫入 `activeContext.md` 待辦清單，不可無限重試造成 restart loop（可參考 `docs/AGENT_QUICK_REFERENCE.md` §4.6 的 debug patch 教訓）。

## 使用規則

1. 本文件只放「規則與原則」，實際串接程式碼放在系統程式碼裡（例如未來的 `notify_tasks.py` 擴充）。
2. 待補項目（1-3-2、1-3-3）由人逐步補齊實際串接方式後，再回來更新本文件狀態。
3. 若发现禁開 UI 原則被違反（例如某功能只能用 GUI 做），需記錄到 `activeContext.md` 待辦清單，討論替代方案。
