# auditBasis.md — 審圖的法規依據、標準、檢查清單

> ⚠️ **這是 Agent 做審查決定時的唯一依據。找不到對應條目就不能自己判斷，必須標記 `input-required` 並記錄到 `activeContext.md` 的「需要的決定」區塊。**

> 目前這份檔案是骨架，尚未填入實際法規內容 — 這是整個系統目前最大的缺口：`ARCHITECTURE_CURRENT.md` 顯示現有系統只做到訊息流轉/watchdog，還沒有實際審圖規則。請填入實際使用的法規/標準。

## 結構建議

```
## <法規/標準名稱>（例：建築技術規則建築設計施工編）
- 版本/生效日期：
- 適用範圍：
- 對應檢查項目：
  - [ ] 條文 XX：說明、判定標準、常見誤判
- 來源連結/檔案：
```

## 使用規則

1. 每次審圖判斷前，Agent 必須先在本文件搜尋對應條目。
2. 找到 → 依條目判斷，並在 `result` 裡引用條目編號（可追溯）。
3. 找不到 → 不可自行判斷，任務狀態設為 `input-required`，並在 `activeContext.md` 記錄「需要新增的審查依據」。
4. 條文更新 / 新版法規發布 → 直接更新本文件對應條目，並在 `progress.md` 記一筆變更記錄（版本何時更新、為何更新）。
5. **本文件只放「判斷依據」，不要放任務流程/系統操作** — 那屬於 `systemPatterns.md`。
